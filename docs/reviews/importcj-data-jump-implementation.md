# 数据跳动风格实现与验证

日期：2026-10-19。范围：风格 7 的前端运行、揭晓、后台选择入口及隔离测试。本记录覆盖本地实现与验证；提交及发布结果以对应部署记录为准。

## 实现行为

- 同一个 `ResultView` 拥有跳动卡片与结果卡片。准备时只在 JavaScript 中保存已确认名单，运行期 DOM 只包含候选值；揭晓时原位改值、移除蓝色状态，不调用普通 `setResult` 重建首屏。
- 候选每 90ms 更新；单次停止后等待 500ms，按 `min(420, 2400 / 当前首屏人数)` 逐张锁定。未锁定卡片继续跳动，锁定卡片恢复已配置的结果主题、字段颜色和字号。
- 本轮字段数取候选和确认结果的最大显示字段数。字号按整轮数据与初始候选快照测量，跳动不重新测量。新候选只接纳本轮已有字段结构；新的结构留到下一轮，异常长值沿用现有省略号处理。
- 首屏人数来自既有分组分页模型，不受 `maxrollnum` 限制。后续结果页使用原来的揭晓入场，不重复候选跳动；首屏最后一张锁定后等待 2500ms，再启动 4000ms 翻页倒计时。
- 缩放、CSS zoom、控制坞移动复用既有布局。普通缩放保留节点；容量变化时按本轮稳定的 winner 对象保留锁定记录，重新计算当前首屏待揭晓队列。
- `screenimportcj-jump.js` 只管理候选 tick 和揭晓定时，不创建 DOM、不计算布局、不访问接口。
- 公共舞台仍使用 `starting/drawing/result`。揭晓子状态由 ImportCJ 管理，专用包装层在每次状态同步后重新应用按钮门禁。
- 开始时仍只调用一次原 `savelucker`。风格 7 跳过旧滚动列表、3D 初始化和遗留停止计数。启动视频结束且 3 秒保护时间结束后才允许停止；视频播放拒绝或错误会继续启动。回调通过 runId 隔离。
- 停止时暂停抽奖音效，首张揭晓时播放结果音效。关闭后的延迟背景音乐恢复也检查 runId，避免新一轮被旧回调影响。
- 页面隐藏时暂停候选更新；若已在揭晓则静态完成首屏并收尾。减少动态效果时使用静态候选，停止立即完成。关闭、ready、销毁和 pagehide 清理本轮调度。
- 后台新增“数据跳动”预览卡及专属说明，仅显示准备页强调色和既有共用字段/结果/音效设置；无未接入的速度或数量配置。风格 7 的 CSS 仅在相应大屏模板条件下加载。
- 预览 SVG 使用用户附件 `files.zip/7.svg`，检查无脚本、外链资源、事件属性或 foreignObject；未采用附件的第二舞台实现。

## 待真实环境验收

本地没有 PHP，业务控制器为加密源码。后台序列化 `flytype=7` 已验证，但不能据此认定服务端会保存和回读 7。发布前或测试环境需验证：

1. 活动后台及系统默认配置选择数据跳动，保存后重新打开仍为 7，其他风格的原参数仍保留。
2. 使用测试活动确认模板实际编译、CSS/AMD 资源加载、字段隐私和启动视频行为。
3. 在明确授权的测试开奖中检查真实接口响应、轮次奖品结构及音频权限。

没有改变公共 `screen-stage-ui.js`、`screen-prize.js`、停止方式编辑页或数据库。
