# 升级 5.3.8 + 切换 PHP 8.2 操作手册

**本次已通过正式站在线升级，结果见[执行记录](5.3.8-execution-2026-11-06.md)。执行路线见[正式站在线升级执行单](5.3.8-direct-online-runbook.md)；下面 A2～A5 的预先取得新版代码、提前合并流程不适用于本次执行。**

配套清单：[5.3.8-customizations.md](5.3.8-customizations.md)、[在线更新覆盖核对](5.3.8-online-overlap.md)。服务商原文：《升级5.3.8以上版本后切换到php8.2版本》（语雀）。

升级前的初始备份只有文件；正式维护窗口已完成 287 张 MyISAM 表的一致性导出及隔离恢复验证。现在本地 `vendor` 分支为 5.3.8（`f7ac9e5`），`main` 已合并（`d947490`）。详见[执行记录](5.3.8-execution-2026-11-06.md)。

约定（执行前替换成实际值）：

| 占位 | 含义 | 实际值 |
|---|---|---|
| `SITE` | 站点根目录（后台首页底部可见） | `/www/wwwroot/________` |
| `DB` | 数据库名 | `________` |
| `PHP7` | 当前 PHP 版本目录 | `/www/server/php/__/bin/php` |
| `PHP82` | 新 PHP 目录 | `/www/server/php/82/bin/php` |

整体分两段：**A. 提前准备（不停机，可花几天）**，**B. 正式窗口（约 1.5～2 小时停机）**。

## A. 提前准备

### A1. 确定窗口
- [ ] 查活动排期，选一个前后各至少 1 天没有活动的时段，夜间优先
- [ ] 提前通知使用方：窗口内大屏、签到、投票、评分不可用

### A2. 拿到 5.3.8 原版代码（二选一）
- [ ] 方式一（推荐）：向服务商索要 5.3.8 完整代码包
- [ ] 方式二：在测试站（快照克隆出的服务器或另一站点 + 数据库副本）执行后台在线升级，再下载代码。注意确认授权是否允许测试域名

### A3. 合并到本地 main

```bash
git switch -c vendor --track origin/vendor # 首次执行；已有本地 vendor 分支时改为 git switch vendor
# /path/to/v538 为解压后的 5.3.8 代码目录
rsync -a --delete --exclude-from=.gitignore --exclude=.git --exclude=vendor/ /path/to/v538/ ./
git add -A
git commit -m "vendor: upgrade to 5.3.8"
git checkout main
git merge vendor
git diff --name-only --diff-filter=U    # 冲突文件
```

- [ ] 逐个解决冲突：保留新版逻辑，再把自定义改动加回去
- [ ] `config/middleware.php` 中 5 个自定义中间件仍在
- [ ] `composer.json`、`composer.lock` 使用新版（以 vendor 分支为准）
- [ ] 对比新版自带的 SQL 和 `database/migrations/` 中的 3 个自定义迁移，确认没有同名字段冲突
- [ ] 提交合并结果

### A4. 本地 PHP 8.2 测试
- [ ] 本地切到 PHP 8.2，执行 `composer install`，并用 `php start.php start` 启动
- [ ] 按“B6 验证清单”逐项走一遍
- [ ] 运行前端检查：`tests/importcj-config`、`tests/importcj-result`、`tests/liuyancj-danmaku`

### A5. 生成部署包
只打包相对原版改过和新增的文件，这样覆盖范围最小：

```bash
git archive -o ~/Desktop/custom-5.3.8.tar.gz main \
  $(git diff --name-only --diff-filter=AMR vendor main -- app config public database)
tar -tzf ~/Desktop/custom-5.3.8.tar.gz | wc -l    # 核对文件数
```

- [ ] 部署包已生成，并且文件数和清单一致

## B. 正式窗口

全部在宝塔终端执行。每步完成后在右侧记下时间。先设置变量（终端断开重连后要重新设置）：

```bash
SITE=/www/wwwroot/你的站点目录
```

下面命令里的 `DB`、`PHP7`、`PHP82` 按上表手动替换。

### B1. 备份（约 30 分钟）　　时间：____
- [ ] 云控制台给系统盘（和数据盘）做快照，等状态变为“完成”
- [ ] 打包站点（含 `vendor/` 和 `public/attachment/`）：

```bash
cd /www/wwwroot && tar --exclude="$(basename $SITE)/runtime" -czf /data/backups/hd.ufunet.cn/site-backup-$(date +%F).tar.gz "$(basename $SITE)"
```

- [ ] 暂停站点及后台任务的业务写入；287 张表均为 MyISAM，不能用 `--single-transaction` 代替一致性备份。导出期间保持写入暂停：

```bash
set -o pipefail
mysqldump --lock-tables --routines --triggers -u root -p DB | gzip > /data/backups/hd.ufunet.cn/db-backup-$(date +%F).sql.gz
```

- [ ] 检查备份并下载到本地：

```bash
ls -lh /data/backups/hd.ufunet.cn/{site,db}-backup-$(date +%F).*
tar -tzf /data/backups/hd.ufunet.cn/site-backup-$(date +%F).tar.gz | head
zcat /data/backups/hd.ufunet.cn/db-backup-$(date +%F).sql.gz | tail -1    # 应为 "-- Dump completed ..."
```

- [ ] 记录当前计划任务内容和禁用函数列表，回滚时要用

### B2. 后台在线升级到 5.3.8+（约 10 分钟）　　时间：____
- [ ] 升级前确认自定义字段存在：

```sql
SHOW COLUMNS FROM mibov3_huodong_configlivemark LIKE 'show%score';
```

- [ ] 后台执行在线升级；完成后后台显示版本 ≥ 5.3.8
- [ ] 再执行一次上面的 SQL，确认 `showpwscore`、`showdecscore` 仍然存在

### B3. 覆盖自定义代码（约 5 分钟）　　时间：____
- [ ] 通过宝塔文件管理把 `custom-5.3.8.tar.gz` 上传到 `$SITE`
- [ ] 解压覆盖：

```bash
cd $SITE && tar -xzf custom-5.3.8.tar.gz && rm custom-5.3.8.tar.gz
grep -c "ScoreVisibilityMiddleware\|PrizeImportQuantity" config/middleware.php   # 应为 5
```

### B4. 安装并切换 PHP 8.2（约 30 分钟）　　时间：____
- [ ] 宝塔软件商店安装 PHP 8.2（文档要求 8.2.35）
- [ ] PHP 8.2 设置 → 安装扩展：fileinfo、opcache、redis、imagemagick、sg14、event（igbinary、zstd 会自动装上）
- [ ] PHP 8.2 设置 → 禁用函数：删除 exec、putenv、shell_exec、proc_open、pcntl_fork、pcntl_alarm、pcntl_wait、pcntl_signal、pcntl_signal_dispatch
- [ ] 把命令行 PHP 版本设为 8.2，并确认：

```bash
php -v          # 应显示 8.2.x
php -m | grep -Ei "redis|event|fileinfo|imagick|opcache"
```

### B5. 依赖、计划任务、重启（约 40 分钟）　　时间：____

```bash
cd $SITE
composer self-update
composer install          # 文档说遇到提示连按两次回车，约 20 分钟
```

- [ ] `composer install` 没有报错退出
- [ ] 计划任务：按服务商文档截图修改。一般是把命令里的 `PHP7` 路径换成 `PHP82`
- [ ] 重启服务器，等 5 分钟；后台首页显示 PHP 8.2.35

### B6. 验证清单（约 30 分钟）　　时间：____
- [ ] 后台登录、活动列表正常
- [ ] 大屏能打开，WebSocket 连接正常（手机发一条消息，大屏能收到）
- [ ] 手机端签到、留言正常
- [ ] 导入抽奖：数字跳动样式、结果卡片、奖品图片，以及第二轮会清空上一轮中奖卡片
- [ ] 评分：大屏专家分数显示开关、扣分与最终得分显示开关都能生效
- [ ] 红包墙：奖品导入数量限制、v2 主题素材
- [ ] 投票：投票页、排行榜、PK 大屏
- [ ] 留言抽奖弹幕、普通抽奖星环样式
- [ ] 查看日志里有没有新的报错：

```bash
tail -n 100 /var/log/mibo.log /var/log/miboout.log
```

全部通过后，通知使用方恢复使用。

## C. 回滚

触发条件：B5 之后核心功能（大屏、签到、抽奖）不可用，且 30 分钟内修复不了。

- **首选**：云控制台用 B1 的快照回滚系统盘，重启后整机恢复到升级前
- **没有快照时**：
  1. 宝塔把命令行 PHP 和站点 PHP 切回原版本，计划任务改回 B1 记录的内容，并恢复禁用函数列表
  2. 恢复代码和数据库：

```bash
cd /www/wwwroot && mv "$(basename $SITE)" "$(basename $SITE).failed" && tar -xzf /data/backups/hd.ufunet.cn/site-backup-YYYY-MM-DD.tar.gz
zcat /data/backups/hd.ufunet.cn/db-backup-YYYY-MM-DD.sql.gz | mysql -u root -p DB
```

  3. 重启服务器，然后走一遍 B6 验证
